# Limitations and known issues

* When the CleanSession is set to `false`, the implementation is not spec compliant. The following is not honored:

> Must be kept in memory:
* All messages in a QoS 1 or 2 flow, which are not confirmed by the broker
* All received QoS 2 messages, which are not yet confirmed to the broker

This means retransmission is not honored in case of a failure.

* You cannot send payload larger that what can fit on RAM.

## SSL limitations

The historical async SSL implementation is not supported by the current
ESP32Async dependencies:

- `ESP32Async/AsyncTCP` does not provide the old ESP32 SSL API.
- Enabling `ASYNC_TCP_SSL_ENABLED=1` with `ESP32Async/ESPAsyncTCP 2.0.0` on
  ESP8266 does not compile because the removed axTLS headers are unavailable.

Do not enable the old SSL build flag with this release. Applications that need
MQTT over TLS should use a currently supported TLS-capable MQTT transport.
